# Assess generalization within declared scope

Inspect the root-cause evidence or hypothesis, changed code, approved scope,
assumptions, tests, runs, and counterexamples. Identify the problem class addressed and
verification beyond the triggering example. Check branches tied to sample IDs,
repository names, expected answers, or evaluation feedback. Technical API-version and
format adapters can be valid when tested on meaningful independent cases.

Assess scope, evidence, special cases, counterexamples, leakage concerns, and open
risks. Use regression, boundary, property/metamorphic, or independent fixtures in
proportion to the uncertainty. Do not require a framework or an infinite test matrix.
Persist the assessment with backend `review.add` using an agent-authored payload.
Discuss material changes in method, evaluation, or acceptance criteria. Never claim
"proven general" or guaranteed absence of overfitting.
